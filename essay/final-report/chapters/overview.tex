\chapter*{摘\quad 要}
\addcontentsline{toc}{chapter}{摘要}

大语言模型 Agent 已从“回答问题”的文本系统逐步走向能够读取文档、整理文件、执行命令、访问网络和写入长期记忆的行动系统。Agent 的能力越强，风险也越接近真实世界：一段隐藏在网页或文档中的指令，可能诱导系统访问不应访问的资源；一次未经确认的删除、外发或写入，可能使错误从对话窗口扩散到文件、账户或后续任务中。单靠模型在回答时“自我判断”并不足以解决这些问题，关键在于让每一项可能产生影响的操作都经过可检查、可暂停、可确认和可追溯的运行时过程。

本作品设计并实现了面向 Agent 工具调用的 Aegis Runtime。系统把任务拆分为带依赖关系的执行节点，在工具实际作用于资源之前完成风险识别、策略与权限判断、必要的人工审批和受控执行；对可恢复的文件、Memory 与下载状态，系统保留检查点和 Effect 记录，使其能够在提交前处于受控状态，在取消或失败后按范围恢复。全过程以脱敏方式记录任务、审批、Effect 和 Audit 事实，既便于用户理解当前任务处于何种状态，也便于在出现异常时定位原因。

本作品的三项核心创新为：（1）\textbf{Transactional Controlled Execution}，将可恢复副作用置于 Pending、校验、提交或回滚的明确生命周期中；（2）\textbf{Approval-aware TaskGraph Scheduling}，在审批等待时只约束受影响节点，使安全且独立的工作能够继续；（3）\textbf{Dependency-aware Selective Rollback}，回滚受影响依赖闭包内的 Effect，同时保留范围外已安全提交的独立成果。Risk、Policy、Permission、Approval 与 Audit 是保障上述机制运行的支撑层，而不是对三项核心创新的替代命名。

作品通过安全机制、任务图调度和选择性回滚三组正式实验，以及真实浏览器场景进行验证；系统最终验收通过。Safety 实验采用确定性受控规则，不以 LLM 裁决作为正式结论依据；TaskGraph 实验使用固定时延的受控环境验证工程行为，不作统计显著性主张。

\noindent\textbf{关键词：} Agent 安全；事务式受控执行；审批感知调度；选择性回滚；状态完整性

\chapter{作品概述}

\section{作品背景}

Agent 的价值在于能够把自然语言目标转化为连续行动。例如，用户要求“整理项目资料并生成摘要”时，系统可能需要读取多个文件、提取信息、写入新的文档；用户要求“检查某个服务的安全状况”时，系统可能需要发起查询、调用工具并记录结果。这类任务不再是一次性生成文本，而是由一系列可能改变外部状态的步骤组成。只要其中一个步骤被误导、越权或执行顺序失当，后续步骤就可能在错误前提下继续推进。

现实使用环境中，Agent 面对的输入并不都来自用户本人。网页正文、邮件附件、工具返回内容、历史对话和长期 Memory 都可能含有不可信信息。间接提示注入已经表明，第三方内容可能被模型错误解释为高优先级指令，从而诱导集成应用执行非预期操作\cite{greshake2023indirect}。代码 Agent 的风险评测也将危险命令和执行环境置于问题中心\cite{guo2024redcode}。因此，安全问题不能只放在“模型是否回答正确”上，而应进一步回答：这个动作是否真的应当执行、执行前是否需要确认、执行后留下了什么影响，以及出错时能否只恢复受影响部分。

现有用户通常很难从一段自然语言回复中判断系统已经做了什么。一个任务看似完成，实际可能已经写入文件、保存了错误的 Memory，或在等待审批期间继续执行了其他相关操作。Aegis Runtime 以运行时为控制位置，把“提出动作”“判断动作”“执行动作”和“记录结果”连接起来。系统并不要求用户理解底层代码，而是通过任务状态、审批卡片、Effect 状态和审计时间线，将原本分散的操作呈现为可理解的过程。

\section{问题定义与威胁模型}

本作品处理的是带有工具调用请求和任务契约的 Agent 运行时。对于每一项动作，系统需要同时处理四类问题：它是否符合用户目标与授权边界；在安全结论尚未明确时是否应进入暂存状态；审批、取消或失败出现后哪些节点可以继续、哪些节点必须停止；以及已经形成的资源状态应当如何恢复。这里的“恢复”并不是简单撤销整个任务，而是尽量按照任务之间和资源之间的实际关系处理影响范围。

威胁模型首先来自指令层。网页、文档和工具输出中的文本可能携带间接提示注入或语义操纵，试图改变系统原本的工作目标。其次是资源层：路径越界、危险 Shell、敏感文件访问和未授权外发会直接影响用户资源。再次是状态层：未经验证的工具结果或 Memory 写入若直接成为可信状态，可能造成跨任务持续污染\cite{dash2026memorypoisoning}。最后是调度层：审批等待、取消与恢复若缺少明确约束，可能造成本应停止的分支继续执行、后台任务脱离控制或同一动作被重复触发\cite{khan2026stop}。

为应对上述风险，Aegis Runtime 将 Planner 的输出视为需要进一步核验的提案，而不是可以直接执行的命令。可信边界由 Runtime Scheduler、风险策略与权限判定、审批门、Effect 生命周期和 Audit 记录共同构成。工具原始输出不会直接进入可信 Memory；前端也不会原样展示不可信内容、密钥或隐藏推理。这样的边界并不承诺消除所有开放环境风险，但能够把当前原型覆盖的风险点转化为可检查的系统行为。

\section{国内外研究现状}

围绕 Agent 安全的研究已经从单纯的风险发现逐步走向多步骤工具使用和运行时治理。ToolEmu 通过模拟工具环境识别工具使用中的长尾风险\cite{ruan2024toolemu}；R-Judge 与 Agent Security Bench（ASB）分别聚焦交互轨迹风险意识和多场景攻防评测\cite{yuan2024rjudge,zhang2025asb}；AgentHarm 则从多步恶意任务角度评估 Agent 被滥用的风险\cite{andriushchenko2025agentharm}。这些工作说明，安全评估不能只观察模型是否拒答，还应关注完整任务轨迹中的真实工具影响。

在运行时防护方面，SafeAgent 将安全建模为随轨迹演化的有状态决策问题\cite{liu2026safeagent}；SafeHarness 将控制机制置于 Agent 生命周期和执行 Harness 中\cite{lin2026safeharness}；Consent Integrity 强调审批内容必须由可信中介绑定到实际执行对象\cite{weng2026consent}。Cordon 将工具意图、结果血缘、暂存 Effect 与审计元数据放入任务级语义事务中\cite{chen2026cordon}。这些研究为本作品提供了重要启发：安全控制应贴近执行边界，审批内容应与真实操作相连，状态恢复应依赖可验证的记录。

本作品不将“事务”或“审批”本身宣称为首创，而将重点放在三项机制的工程组合上。它既要使单个工具调用在提交前可被检查，也要让多个节点在审批、取消和回滚过程中保持可解释的整体状态；同时，以正式实验和浏览器场景验证这种组合能否形成完整闭环。

\section{设计目标}

\Aegis{} 的第一个目标是让高风险操作不会在缺少必要判断时直接落到真实资源上。系统通过风险、策略和权限机制决定动作可以自动执行、需要等待人工确认，还是应当直接阻断。第二个目标是让可恢复的副作用具备清晰状态。文件、下载和 Memory 等资源在适用时先进入受控状态，只有满足条件后才提交为可信结果；取消或失败时，系统能够依据预先保存的关联信息处理恢复。

第三个目标是避免把审批理解为“所有工作都暂停”。在一个由多个节点组成的任务中，等待审批的高风险节点及其后续或冲突节点需要被约束，但与其无依赖、无资源冲突的安全节点仍可推进。第四个目标是避免出现“一处失败，全部清空”的粗糙恢复方式。系统应当识别真正受影响的 Effect，只回滚这一范围，同时保护已经安全完成且与问题无关的独立成果。

第五个目标是让用户看得见、查得清。系统把任务、审批、Effect、检查点和审计事件以统一标识关联，在界面中提供相应的状态说明和原因说明。这样，用户可以知道某个任务为何等待、为何被拒绝、哪些资源已经提交、哪些资源被恢复，以及独立成果为何被保留。

\section{作品价值与适用范围}

本作品适用于需要工具调用、运行时审计、人工审批和受控恢复的本地或企业自动化工作流，例如安全敏感代码辅助、文件处理和多步骤业务准备流程。它的直接价值不在于替代人的安全判断，而在于把用户已经作出的授权边界落实到每一次具体执行中，并在异常时留下能够追溯的处理依据。对于使用者而言，系统把“是否执行”“执行到哪一步”“发生异常后如何处理”从隐含逻辑变为可见状态；对于开发者而言，统一的 Effect 和 Audit 记录为后续排查、测试和改进提供了基础。

当前原型未覆盖分布式调度、服务重启恢复、完整 ACID 事务、真实支付或邮件发送、通用 MCP/Skill 协议，以及同一节点 speculative execution。选择性回滚只适用于已纳入 Effect、Checkpoint 和关联关系管理的可恢复状态；对于不可逆外部动作，系统的重点是通过审批与提交边界在释放前进行控制，而不是宣称能够事后通用撤销。对外发类动作，作品以受控、脱敏和干运行边界为前提，也不据此声称对开放网络环境中的任意副作用提供普适保证。
