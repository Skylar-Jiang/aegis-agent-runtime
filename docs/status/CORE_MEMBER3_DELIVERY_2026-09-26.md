# 成员 3：本轮 Core 优化交付说明

日期：2026-09-26。分支：`experiment/core-hardening-preview`。提交入口：[PR #6](https://github.com/chiyi-creator/aegis/pull/6)，目标分支 `aegis-core`。

本轮围绕组长 C1–C7 共通线，补齐授权、实际执行、恢复、密码证据与前端展示的接线和一致性问题。没有自行替换团队的公共协议，也没有引入自创密码算法。代码、回归用例、真实服务实验和公开证据随 PR 提交，交由组长审阅合并。

## 1. 现在可以跑通什么

真实工作台已经串起以下流程：

1. 创建会话与任务，确认有版本的任务契约。
2. 服务端依据用户/Profile、Skill、契约和系统规则计算实际权限；请求中自填权限不能扩大服务端上限。
3. 网关校验实际工具、动作、资源、参数和契约绑定；需要审批的请求先等待批准。
4. 执行前重新读取可信授权状态，在 SQLite 事务中登记接纳和额度消费。
5. 文件、记忆写入进入原 Runtime 的检查点、待提交、提交和 Effect 流程，返回真实文件及持久化回执。
6. 审计记录关联契约、调用、决策和结果，导出 SM3 链与 SM2 签名证据及检查点；独立验证器用公钥核验，篡改样本会被拒绝。
7. 工作台刷新、按编号重开仍能读取已保存进度；恢复失败可见，明确重试前核对实际 Effect 状态。

密码学实现采用 JCS 规范化、SM3 摘要和 OpenSSL SM2 签名/验签。真实服务实验核对签名、事件关联和真实文件副作用，不以页面显示“成功”代替后端执行。当前签名证据不应被称为完整的能力令牌及持有者调用证明协议。

## 2. 本轮后端修改

| 问题 | 最终处理及作用 |
| --- | --- |
| Core 与原 Runtime 的副作用/恢复接线不完整 | 文件及记忆写入复用原受控执行；返回 checkpoint、Effect 等真实回执，保留原 Runtime 入口。 |
| 权限、参数与实际工具语义不一致 | 从可信 Profile/Skill/系统来源计算上限，交叉检查工具、动作、效果和资源；修正 Windows 路径大小写及别名问题。 |
| 重复调用与变参 | 原子占位、完整请求指纹和持久化成功结果；重复成功请求返回原结果，同 ID 换参数被拒绝，未知执行不自动重放。 |
| 无限制阶段未计数、变更范围后重置额度 | 始终累计任务/契约/授权用量；旧数据首次计数时按已有执行历史恢复，切换工具、Skill 或契约版本不能清零已用额度。 |
| 并发额度误拒绝，Linux CI 暴露竞争 | 区分带所有权标识的接纳前 CLAIMED 与已消费额度的 ADMITTED；两个未接纳请求不互相占满额度。用双屏障稳定复现，验证限额 1 时恰有一个实际执行。旧格式不明状态仍保守计数。 |
| 重复契约确认重置时间、审批或任务状态 | 同版本同确认人幂等；冲突确认拒绝；确认审计完成标记可修复中断，不把已执行任务退回 READY。 |
| 签名决策中的策略版本不准确 | 权限与版本取自同一可信快照，记录实际策略版本，同时保留契约所绑定版本。 |
| SQLite 等待阻塞 HTTP，取消与状态保存竞争 | 完整短事务在线程完成，只读事务不申请写锁；未接纳占位仅由持有者释放，已接纳未知结果保守保存，已落盘成功结果不降级。 |
| 权限收紧、取消与执行同时发生 | 跨进程接纳锁对执行和安全变更排序；变更返回后使用新状态。不会宣称能撤销已完成的不可逆副作用。 |
| 取消后后台执行或写入仍继续 | 执行监视器等待子任务结束再回滚；事件追加、不可变证据写入、检查点发布也等待实际工作线程结束，再传播取消。 |
| 检查点和文件/目录读取无界 | 按部署上限有界读取；备份采用分块复制、完整性检查与恢复、临时文件原子安装；新增可配置的单文件 `MAX_BACKUP_BYTES`。 |
| 选择性恢复错误不透明、无法重试 | 保存规划、存储、审计和回滚失败原因；补齐 PENDING 文件清理。明确重试前对照持久化 Effect，已回滚效果不重复执行。 |
| 同时重试恢复会重复回滚 | 每个图的自动恢复、取消清理和手工恢复共享锁；后到请求重新核对状态，拒绝多 Effect 共用 request ID 等歧义数据。 |
| 合法分支事件分页失败、长历史截断 | 区分业务父事件与顺序哈希链，允许同任务较早父事件；跨任务、缺失或未来父事件仍拒绝。Core/SSE/报告继续完整分页。 |
| 边追加边导出出现不同链头 | SQLite/JSONL 原子读取事件及链头，导出一致前缀。EventStore 三个公共方法保持兼容，快照是内部可选优化。 |
| 同一检查点导出重试随历史增长失败 | 已有检查点返回其原来签名覆盖的前缀；需要覆盖新增事件时使用新的检查点 ID。不能改写原锚点来伪造“更新”。 |
| 日志损坏或存储不可用变成通用 500 | 事件查询与证据导出返回结构化错误：无效日志 409、存储/检查不可用 503；不伪装成空列表或有效证据。 |
| 非 UTF-8 文件读取报 500 | 返回明确的 `TOOL_EXECUTION_REJECTED`，保留原文件和保守执行状态，不放宽已接纳失败的重放规则。 |
| 实验记录误用开始时间或复制后的 mtime | 优先使用有效的生成、完成、创建时间，再回退到开始时间或文件时间；异常、缺失、超大证据独立显示为不可用。 |

完整历史改动和实现边界还见 [持续交付记录](CORE_HARDENING_HANDOFF.md)。

## 4. 接口对齐

未改动 C1–C7 公共模型、六字段 SignedEnvelope、SignatureProvider 方法、JCS/SM3/SM2 字节协议或冻结密码向量。新增内容均为兼容扩展，详见 [Core 接口说明](../interfaces/core_v1.md) 和 [密码/审计接口](../interfaces/crypto_audit_v1.md)。

| 新增/明确的接口 | 约定 |
| --- | --- |
| `GET /api/v1/tasks/{task_id}/snapshot` | 只读返回 task 与 latest_request；过期契约的请求省略，不返回权限凭据、不执行操作。 |
| `GET /api/v1/experiments/core` | 返回 recorded、runs、unavailable；仅读取已列入清单的本地历史证据。 |
| `POST /api/task-graphs/{graph_id}/retry-recovery` | 明确重试当前进程中已注册图的恢复失败；图快照兼容增加 recovery_failures。 |
| `GatewayDecision.versions` | policy 是实际可信策略版本；contract_policy 保留契约版本来源；映射字段类型不变。 |
| 同 checkpoint_id 再导出 | 原检查点锚定前缀不变；历史增长需用新 ID 才覆盖新事件。 |

## 6. 保留的工程边界

- 当前仍为单操作员可信后端和本地开发密钥；没有生产认证、多租户隔离、HSM 或独立授权密钥服务。完整 Cap、持有者证明等后续协议仍须按团队计划开发。
- Core 执行与安全变更采用粗粒度接纳锁，优先保证一致性；不声称任意故障下“恰好一次”，不自动重放未知结果。
- 图调度状态仍在进程内，服务重启不会重建整个图；Core 会话、契约、请求、结果、额度和事件的持久化不等于图调度持久化。
- 证据包上限仍为 64 MiB。验证针对指定可信检查点范围，`tail_complete=false`；不能证明未锚定尾部未被删除。只有三方法的第三方 EventStore 使用有界重试，持续增长时可能需稍后重试导出。
- 单文件备份上限不等于磁盘总配额；原 Runtime 入口不因共享执行组件就自动具备 Core 全套签名证据。
- 历史性能实验保留原始数据，本次修复未冒称产生新的性能提升百分比。真实 LLM 规划器和真实邮件发送不在本次验证范围。
