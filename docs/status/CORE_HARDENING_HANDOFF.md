## 准确理解边界

- 当前接纳锁按部署状态库串行处理 Core 执行与安全变更，是正确性优先的实现。取消返回前已完成的副作用不会自动回滚；不能解释为任意时刻立即中断已经开始的操作。
- `max_affected_objects` 累计不同受影响资源，`max_bytes` 累计写入 UTF-8/规范 JSON 字节，`max_calls` 累计尝试；失败或未知执行保守占用已预留额度。`max_output_bytes` 限制结果序列化大小；超过时副作用可能已发生，返回 UNKNOWN 而非假装未执行。
- `run_shell` 的资源副作用无法由 cwd 计量，有对象/字节额度时明确拒绝 `LIMIT_UNMEASURABLE`。未建立进程级资源计量前，不伪造受控能力。
- 完整证据包仍限定 64 MiB。游标分页和继续执行后产生新检查点已实现；没有新增“分段证据包协议”或悄悄删除历史。超限显式拒绝，后续分段协议应由团队统一接口后独立开发。
- 原 Runtime 入口继续保留；共享受控执行不代表所有旧 Agent 事件已获得 Core SM2 签名。旧 Core 记忆按 key 一次导入统一存储；后续以 Runtime 记忆为准。
- 本地开发密钥不是 HSM；当前是单操作员可信后端，无生产多租户身份系统。未知执行结果不自动重试；证据仅核验指定可信检查点范围，不能自动证明最新尾部未被删除。
