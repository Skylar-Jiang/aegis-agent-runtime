# Core 机制对照实验

运行：在仓库根目录执行 `backend/.venv/Scripts/python.exe scripts/experiment_core_ablations.py`，或 `uv run --project backend --no-editable python scripts/experiment_core_ablations.py`。

脚本在独立临时目录建立工作区和 SQLite 状态，每次生成新 SM2 密钥。结束后删除私钥与临时目录，保留 `.runtime/review-fixes/ablations/<run>/results.json`、`measurements.csv` 和 `public-keys.json`。JSON 含逐次尝试、真实写入账目、落盘内容、签名对象和完整组行为事件，可用输出公钥复验签名。

三组使用相同的 `CoreToolExecutor.write_file`、`SafePathResolver`、4096 字节限制、已确认契约及 `PermissionResolver`。计数器在真实文件操作完成并重新读取验证内容后递增；相同内容再次写入仍算一次实际写入。

| 组别 | 保留与移除 |
| --- | --- |
| 仅权限 | 权限交集、执行前当前权限复查、真实受限工具；实验 harness 不绑定请求 ID 与不可变参数，不缓存执行结果。 |
| 权限 + SM2 | 在上一组增加真实 SM2/SM3 请求、决策和结果证据；签名绑定证据载荷，但没有增加请求 ID 的执行绑定或结果缓存。 |
| 完整 Gateway | 未修改的当前 `ToolGateway`、SQLite `CoreStateStore`、`SqliteEventStore`、SM2 `FileEvidenceRecorder` 和当前权限来源。 |

另设一项单机制消融：完整 Gateway 不配置 `permission_provider`，保持其余配置和初始授权相同。权限源收紧后，网关只能看到已存初始授权。此改动仅存在于实验 harness，没有为服务增加关闭开关。

2026-09-23 实测结果（基于 `d654df7` 加本轮工作区修复，运行目录 `20260923T045538Z-331f32e6`）：

| 场景 | 仅权限实际写入 | 权限 + SM2 实际写入 | 完整 Gateway 实际写入 |
| --- | ---: | ---: | ---: |
| 正常请求 | 1 | 1 | 1 |
| 相同 ID：首次 + 同实例重试 + 重新构造网关后重试 | 3 | 3 | 1 |
| ALLOW 评估后，同 ID、同授权路径更换内容并再次评估 | 1（替换内容） | 1（替换内容） | 0（绑定冲突） |
| 评估后移除系统 ALLOW，执行前复查 | 0 | 0 | 0 |

移除当前权限来源的单机制消融在权限收紧后写入 **1 次**，完整组写入 **0 次**。两组基线保留当前权限复查，因此该场景是共同拒绝的对照，并未故意移除基线的权限检查。

共完成 **13 案例**。**26 个真实签名对象**全部通过独立构造、仅持公钥的验证器复验；9 个有签名的案例各修改一个证据载荷，**9 次均被拒绝**。签名对象去重复用不等于工具执行去重：签名基线的合法重试仍实际写入三次。脚本同时断言每个场景的写入次数，失败时以非零状态退出。

这是 C2–C4 请求与执行控制、C5 完整组事件以及 C6 签名证据的限定控制实验。基线是明确列出移除机制的实验构造，不代表历史版本。共同使用直接文件适配器是为隔离网关机制；未测 Runtime 恢复、HTTP/UI、C1/C7 或统计性能，也不替代这些路径的独立验收。本实验参数替换发生在评估后，没有声称覆盖人工审批流程。事件读取进行了现有存储验链，未将其解释为独立锚定的尾部完整性证明。
